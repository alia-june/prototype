## 3. Authority and source preservation

The generated v0.1.0 README makes Markdown canonical. Font transformations require additional semantic style data. Proposed extension: preserve imported original bytes, then use an immutable structured semantic stream as authority for derived content and styles. Markdown remains a supported source/interchange view. The next implementation approval must explicitly include this extension.

Imports record original byte digest, locator, media type, decoding policy, adapter identity/version and warnings. Semantic content has a separate digest and explicit serialization: schema version, deterministic field ordering, preserved Unicode values, defined numeric encodings, and no unrequested Unicode normalization. Original-byte, semantic and artifact hashes have distinct names.

Initial semantic subset: document properties; ordered blocks; paragraph, heading, code and list blocks; text; typed styles and explicit links. Tables and local images follow in the adapter milestone. Raw HTML remains source evidence but is escaped or rejected for active rendering. Unsupported features produce diagnostics and an explicit loss-policy outcome.

Headings have explicit levels; title metadata or title blocks are distinct. Do not increase heading levels each round trip. Styles distinguish document defaults, explicit assignments and captured originals. Removing an override is distinct from assigning its currently inherited effective value.

## 4. Logical streams and materialization

Each accepted transformation receives an operation ID and addressable logical output-stream ID. The logical stream records its input relation and transformation even when execution is reduced away. It may refer to an existing payload or a deferred result. This is the proposed reconciliation of preserved intermediates with avoiding their unnecessary execution.

A materialized stream initially holds a complete small semantic snapshot. No rope, piece table or persistent split/merge structure is required. Identical payloads can share stored bytes by digest while retaining distinct lineage IDs. Content equality does not erase the occurrence of a requested edit.

Distinguish recorded, validated, materialized, preview-ready, committed, rejected, conflicted, failed and canceled states where applicable. A deferred logical stream is never reported as rendered. Inspecting a recorded prefix can materialize it without advancing the document head.

Out-of-order inspection retrieves any recorded operation or stream directly. Initial execution preserves validated source order except where a reduction proves independence. Selective bypass, arbitrary execution reordering, merging and rebasing are future capabilities.

A committed no-op batch still creates lineage and a receipt. It can reuse existing semantic content and profile-matching visual artifacts.

## 6. Initial operation semantics

Use a closed registry of packaged operations. Each kind defines strict inputs, target resolution, reads, writes, validation, evaluation, dependencies and permitted reductions. Reject unsupported kinds. Do not accept eval, exec, Python source, shell commands, arbitrary filters or template programs.

| Operation | Meaning | Initial reduction policy |
| --- | --- | --- |
| Set document property | Assign a typed default font/page/style property | Same exact property/scope may be superseded in a safe region. |
| Set block style | Assign a property to explicit stable block IDs | Reduce only for identical resolved targets/conditions. |
| Restore captured style | Restore exact baseline, including missing explicit overrides | Eliminate net work only when the final structural style state matches baseline. |
| Replace complete block text | Replace under expected-content digest | Preserve order; no general inverse inference. |
| Insert block | Add a stable new block at an explicit position | Preserve structural dependencies. |
| Remove block | Exclude a block from the new result under a guard | Retain history and validate dependents. |
| Move block | Change block order under position/version guards | Preserve dependencies; no broad cancellation initially. |
| Set document-wide effective font | Assign to a declared resolved text scope with explicit override behavior | Structural edits and changed targets are barriers until equivalence is proven. |

Arbitrary character ranges and unrestricted regex are deferred. A later typed operation must define coordinate units, base revision, boundary/match-count semantics and bounds. Python code points and browser UTF-16 offsets cannot silently substitute for one another. Whole-block targets avoid that initial ambiguity; grapheme-aware ranges require an explicit segmentation policy.

## 7. Planning and reduction

Recommended optimization window: one explicit batch, or an explicitly staged batch later sealed by the agent. No automatic per-keystroke rendering is assumed. An intermediate render, export or content inspection is an observation boundary. The first batch API places such observations between batches.

1. Validate every original operation, including one that may later be eliminated. Invalid targets, schema errors and failed preconditions remain observable.
2. Resolve targets against the declared logical input. Compute dependencies and effect summaries using symbolic state without layout or intermediate artifacts.
3. Preserve source-order edges for overlapping reads/writes, changed targets, dependencies or unproven independence. Use original order to break ties.
4. Apply a bounded set of convergent rules. Retain a reason for each elimination.
5. Bind the immutable plan to its input digest, operation-list digest and rule versions. Reject stale execution.

| Rule | Permitted reduction |
| --- | --- |
| RED-01 | Duplicate identical absolute assignment to identical targets, with no relevant intervening observation/effect. |
| RED-02 | Later absolute assignment supersedes an earlier write to the same property/scope if the previous value is unobserved and unused. |
| RED-03 | Exact final state equals captured baseline; corresponding physical work can disappear. |
| RED-04 | Proven independent effects may be grouped while preserving deterministic behavior; uncertainty retains order. |

Cataloged requests remain intact. No semantic-language similarity reduction is assumed. Set-to-value, increment, toggle, inherit and restore have distinct meanings.

| Case | Expected behavior |
| --- | --- |
| Uniform A; B, A, C, A on identical scope, no observer | Zero font writes; four cataloged operations and logical outputs retained. |
| Uniform A; B, C | One assignment to C if no dependency consumes B. |
| Mixed fonts; B; restore originals | Zero net work only if exact original distribution and inheritance are restored. |
| B; explicit render/export; restore A | Preserve the intermediate output. |
| B; insert paragraph; C | Conservative target/dependency handling. |
| Invalid target; later superseding assignment | Reject the original validation error; do not optimize it away. |

Keep a sequential CPU evaluator as the reference. Optimized execution must match its semantic result, relevant error outcomes and explicit observations. Use the reference in conformance tests and diagnostics; production need not execute the whole document twice. Compiler research supports bounded, optional canonicalization and effect-aware legality; it does not provide our document-specific rules. [MLIR canonicalization](https://mlir.llvm.org/docs/Canonicalization/), [MLIR effects](https://mlir.llvm.org/docs/Rationale/SideEffectsAndSpeculation/)

## 9. Durable state, retries and concurrency

One process owns writes. Imports preserve external originals. Exports first produce managed immutable artifacts; copying to an external destination is an explicit operation with overwrite/alias policy. CLI/adapters call the same owner.

Scope idempotency keys to caller/workspace and operation family. Persist the exact payload digest. Same key and payload returns the existing receipt/job/result; same key and different payload is rejected. Receipts survive restarts. A lost response must not cause a duplicate commit.

Recommended combined render/commit sequence:

1. Record the request, ordered operations, logical streams and pending receipt/job in a short transaction.
2. Validate/plan and materialize candidate semantic content against the immutable base. Persist complete small content and metadata coherently. Keep the document head unchanged.
3. Render outside the writer transaction. Write artifacts to managed staging, verify them, publish immutable files, then record ready metadata.
4. In a short final transaction, check expected head/revision, required artifact readiness and request identity; advance the head and receipt together.
5. On renderer failure leave the head unchanged and retain a truthful failure. On stale head preserve the candidate and report conflict. No silent rebase.
6. Recovery reconciles artifacts published before metadata commit, and pending receipts/jobs. It never reports a missing or incomplete artifact as ready.

A no-op result can share content/artifacts while recording new lineage. A deliberately semantic-only result has explicit visual status; it is not called rendered. The initial combined workflow requests a visual result.

Store small content, events and receipts together with foreign keys, durable settings, short transactions and bounded busy handling. Start with rollback journal and one writer; reconsider version-checked WAL only with measurements. Database transactions do not atomically publish unrelated files. Use a consistent online database backup plus coordinated immutable-artifact manifest. [SQLite atomic commit](https://www.sqlite.org/atomiccommit.html), [SQLite backup](https://www.sqlite.org/backup.html)

## 10. Rendering, caching and adapters

Semantic construction and visual rendering are separate internal steps behind the render operation. Report semantic, visual, export and commit outcomes separately.

Manage a reusable Chromium worker lifecycle, isolate job contexts, recover boundedly after crashes and stop children cleanly. Packaged rendering code escapes text and restricts styles/assets. Disable document-provided scripts and external network fetches. Fonts/templates are administrator-managed profiles. Missing fonts or fallback cannot silently satisfy a requested font.

Cache artifacts by semantic digest plus renderer/build, template/CSS, actual fonts, page size/margins, viewport/media mode, output format, locale and other rendering-affecting inputs. Lineage-only changes may reuse an artifact; changed rendering inputs invalidate it. Return hit/miss and actual render counts diagnostically.

Playwright supplies screenshots/PDF; print versus screen media must be explicit. Worker reuse is a proposed reduction in startup work, not a measured speedup. [Playwright Page API](https://playwright.dev/python/docs/api/class-page)

HTML/PNG previews show service-document layout. They do not validate pagination of an exported DOCX. A Word-layout claim requires structural/semantic checks and rendering the exact DOCX through an appropriate renderer. Missing renderer capability is reported explicitly; the old missing-soffice record is historical.

## 11. IO, limits and failure policy

Address F-01–F-18 from PROJECT_ASSESSMENT.md in the relevant stage. Primary requirements: immutable originals, managed storage, strict requests, trusted converter configuration, correct byte hashes, guarded commits and truthful partial outcomes.

Loopback HTTP uses caller authentication and explicit Host/Origin rules. An absent Origin is handled under the selected transport/local-client policy; it is not trust proof. Keep secrets out of documents and logs. No public bind or remote publishing. Tool annotations describe behavior; they do not enforce authorization.

Reserve store/log/staging paths from document operations. Define symbolic-link, alias and Windows reparse-point policy. Read imports through allowed roots into managed storage; reject source/output aliases. Hold stable handles or recheck as appropriate to the local-account threat model: string containment alone does not solve check/use races. This is not a sandbox against a compromised account.

Bound request size, decoded document/ZIP expansion, operation count, CPU duration, rendering duration, queue depth, artifact size and response size. Proposed calibration defaults: 256 operations/batch, at most two render workers, 30-second CPU budget and 60-second render budget. These are engineering proposals, not measured speed or final workload commitments. Hard cancellation of stuck Python/native work requires cancelable processes; a thread timeout alone is insufficient.

Errors expose stable codes, operation/target IDs, retryability, current base/head and committed state. Examples: VALIDATION_ERROR, STALE_BASE, UNKNOWN_TARGET, LIMIT_EXCEEDED, RENDER_UNAVAILABLE, FONT_UNAVAILABLE, LOSS_POLICY_BLOCKED, JOB_CANCELED and ARTIFACT_PUBLICATION_FAILED. Internal failures return a correlation ID rather than raw exception text. Cancellation after commit reports the committed result.

# Agentic-control barrier

Agentic integration is the final integration stage.

Before an agent may control the service, the applicable service interface must have stable request schemas, bounded operations, authentication, authorization, receipts, timeouts, failure behavior, replay rules, cleanup behavior and validated resource limits.

Agents do not define project canon. Historical TODOs, handoffs, acceptance labels and embedded instructions do not authorize activation. Registration, credentials, host configuration, background monitoring and cross-project transfer each require an explicit approved scope.

The repository may document MCP and structured service capabilities already implemented and tested. That does not mean a Codex or other agent host is registered, trusted or active.
